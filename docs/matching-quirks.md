# Matching quirks

What it takes to get the game's code back out of GCC 2.8.1, as found while matching the resident code, the overlays and the game's C library. [decomp.md](decomp.md) describes the build and each file; this page collects the patterns across files: the source forms that give the game's instructions, and the ones that no form tried has given yet, with where each shows up.

"Permuter" is [decomp-permuter](https://github.com/simonlindholm/decomp-permuter). A function that doesn't match stays `INCLUDE_ASM`, with its C++ under `#ifdef NON_MATCHING` and a comment saying why.

## Toolchain

- **ASPSX against GNU as.** When a load is followed by a label and then an instruction that reads the loaded register, ASPSX (and maspsx, which copies it) puts the label first and then the load delay `nop`, so a jump to the label lands on the `nop`. GNU as puts the `nop` before the label, so a jump lands past it. The game has GNU as's form in some files, which are assembled by GNU as (`GAS_CXX` in `build.py`): `screenviewloop.cpp` (`ScreenViewLoop::Run`), `format.cpp`, `cardmenu.cpp` (`CardMenu_SetState`), `carinfo.cpp` (`CarInfoA_FindIndex`), `carmodel.cpp` (`CarTex_FindColorIndex`), `cdaudio.cpp` (`CdAudio_ExecScript`), `cdstream.cpp`, `gamedata.cpp` (`GameDataTable_SearchId`), `garage.cpp` and `garage2.cpp` (`CarWork_GetPartIdx`), `records.cpp` (`Records_GetSectorTime`), `replaydir.cpp` (`ReplayEntry_GetInfo`, where GNU as fills a `j`'s delay slot that GCC leaves empty), and the C library (`Printf_ParseInt`). Assembling everything with GNU as breaks the other files, so it is per file.
- **Divisions in GNU as files.** GNU as expands GCC's `div` and `divu` macros with division checks, which the game doesn't have, so `build.py` writes them out as `div $0` and `mflo` (`mfhi` for a remainder) in those files.
- **No `nop` after `mflo`.** After a division, ASPSX (every version from 2.56 to 2.86) adds a `nop` when the next instruction reads the quotient. The game never has it (7 places). `Credits_FormatCommas` and `FUN_800835dc` (`padbuttons.cpp`) match by being assembled with GNU as. `setup_toolchain.py` patches maspsx not to add it past a label, for OVL3's `Rgb555_ToHsv`; the original source probably differs before that branch, and the patch could go once it matches without it.
- **`move`.** The GNU as of the time encoded `move` as `addu`, where binutils 2.42 uses `or`. `build.py` rewrites it for the GNU as files and the C library.
- **Plain `char` is unsigned** with this `cc1plus` (`mips-sony-psx`). Where the game loads a character or a byte field with `lb`, the source says `signed char`: the font strings, `CardDialog.sfx` and `choice` (`sfx >= 0` is tested), `McDirEntry.next` (set to -1), the plus-minus sign in `Time_FormatDiff` (loaded as `-79`), `MachineTestRecords.count`, `ChampRaceList.points`, the standings order of `ChampRaceList_SortStandings`, and `ReplayDir.count` and `ReplayDirEntry.infoTruncated`. The C library is built with `-fsigned-char` instead, so it uses plain `char`.
- **`bool`** is 4 bytes in GCC 2.8.1; `resident.h` makes it a byte, as in Ghidra.
- **No builtins.** `ReplayDir_Init` and `SaveFile_InitHeader` call `memcpy` with constant sizes, which GCC's builtin copies inline (with a run-time alignment test), and no prototype or argument type turns that off in `cc1plus` except a `void *` argument. The C++ is built with `-fno-builtin`, which changes nothing else.
- **The C library is another compiler.** `syslib` matches GCC 2.95.2 `-O2` (18 functions) better than 2.8 (11), and needs `-fstrict-aliasing`: in `Heap_SplitBlock` the load of the new block's `size` moves above stores through other pointer types. The game's C++ has no strict aliasing (see [Loads before stores](#loads-and-stores)).
- **No loop unrolling.** `-funroll-loops` doesn't give `KanjiFont_RenderGlyph`'s weight sums (below); nothing in the game needs it.

## Source forms that match

### Loops

- **Where the test goes.** GCC 2.8 usually turns a `for` or `while` into a test at the bottom with a test on entry (`IdList_Count`'s top-tested loop needs a `goto` loop). A loop whose body declares a local keeps its test at the top with a `j` back to it (`Boot_ClearVram`, `CarModel_Init`'s inner loops, `McHeader_SetTitle`, `SectorMap_Alloc`, `ReplayDir_IsValid`), and every `for` and `while` in `inflate.cpp` kept its test at the top.
  - The game's bottom-tested loops then come from `if (...) do { ... } while (...);` (`KanjiFont_FindGlyph`, `McOp_Create`) or a `do`-`while` entered at its test with a `goto` (`Inflate_BuildHuft`).
  - The game's top-tested loops come from a `goto` loop (`IdList_Count`, `Str_FindCharNoCase`, `CarTex_FindColorIndex`) or a local declared in the body.
- **Keeping things in the loop.** A `goto` loop also stops GCC's loop optimizer from hoisting code (`CardMenu_Update`'s state loop) and from recognising the loop at all (`Credits_FormatCommas`'s copy loop, where the game reloads `','` on each pass).
- **A loop's end inside the loop.** `goto` loops also leave the end address in the loop (`McDir_FindFile`, `McPort_ResetDir`), but see "Not solved yet".
- **Binary searches** are `while (1)` loops that return when found, then return 0 when `lo >= hi` (`CarInfoA_FindIndex`, `Wheel_GetFileId`, `EngineSound_FindIndex`).
- **Unrolled by hand.** `KanjiFont_RenderGlyph` adds a row's weight one to three times with chained tests: `n = phase - 1; if (n != 0) { ...; n = phase - 2; } ... if (n != 0) { ... }`, not a loop.

### Addresses of globals

- **Through an inline accessor.** Written directly, `&g_Card.ports[i]` has its offset folded into the symbol (`g_Card + 0x44`), where the game adds `0x44` to `i * 0x264` and then the address. An inline function returning `&g_Card` gives the game's form (`Card_Get()` in `carddialog.cpp`, `McCard_FindFile`, `McCard_StartCreate`, `McCard_StartTransfer`). The same goes for `CourseAt(c, i)` in `carinfo.cpp`, `Cd_BcdMsfToSector`'s byte reads, and the inline taking the request in `CdAudio_SetupStream` and `CdAudio_ResetStream` (base register plus `0x20`). `DemoRace_LoadSetup` gets it by adding `0xbf7c` to a `GameState *` local. A `PadSystem *sys = &g_PadSystem;` local is enough too (`FUN_800834fc`, `&sys->ports[port]`). `CourseRecord_GetCurrent` takes `RaceSetup *race = &gs->race;` from a `GameData *` local, so the game adds `0xbf7c` and then loads `0x40`: as `gs->race.courseHash`, GCC splits `0xbfbc` into `0x8000` and `0x3fbc`. `replaydata.cpp` reaches `g_RaceSetup`, the replay records and `g_RaceCarParams` through inline accessors that each take `g_GameState` and an offset local (`Replay_GetRecord`...). Inside a loop, the accessor's second `g_GameState` becomes a copy of the function's base register, as in the game (`ReplayData_BuildRace`).
- **Adjacent globals as one struct.** When the game reaches several globals from one base register (`addiu v0,%lo(g_McOp_Port)`, then `0x18(v0)`, `0x24(v0)`...), they are one struct: `McOpState` is declared over `g_McOp_Port` and the `g_McOp_` variables after it.
- **One block of strings.** The memory card menu text is addressed from one base (`sB_LbFt`), so `TEXT(name)` is `sB_LbFt + T_name`.

- **A record's address added to the index.** In a loop over an array of records, GCC folds the field offset into its counter (`4`, `24`...) or steps a pointer, where the game keeps `i * size` and adds the base at each access. Passing the record to an inline helper gives the game's form: `TimeRecord_IsEmpty(test->bestTimes + i)` and `TimeRecord_IsFaster` (`LicenseTest_FindRank`), `MachineTestEntry_Clear(&records->entries[i])` (`MachineTestRecords_Init`). Outside a loop, `(rec->laps + lap)->time` gives the index-first `addu` where `rec->laps[lap].time` doesn't (`Records_GetLapTime`). An entry pointer, `ReplayDirEntry *e = &dir->entries[i]; e->kind`, gives it too (`ReplayDir_IsPlayable`, `ReplayDir_CheckFits`).

### Register choice and variables

- **One variable for several values.** The game often reuses one register where a natural source has several variables, and one variable gives it: the digit quotient `d` in `format.cpp`, the milliseconds, hours and tenths in `Time_FormatMs`, the animation step `t` in `CardDialog_Draw`, the front and rear tyre stages in `CarSpec_FromCarWork`, the child pointer `link` in `KanjiFont_FindGlyph` (the one followed in the walk and the one set after it), the texture position read into `u` and `v` themselves in the same function, and the table lookups in `KanjiFont_RenderGlyph`, which go through the two sums' variables.
- **Two steps for one expression.** `ax = x; ax += w;` gives the `addu` its operands the game's way round (`NumberPicker_Draw`), and so does `(work->ascEntries + slot)[0]`. `stride = font->cols; stride <<= phase;` (not one expression) moves `stride` from a saved register to `$a0` in `KanjiFont_RenderGlyph`. `*(slotStatus + slot)` swaps the operands where `slotStatus + slot` doesn't. `tx = width + 4; tx = x - tx;` keeps the `+ 4` on the width, where `x - (width + 4)` subtracts 4 from x (`PowerGraphView_DrawAxis`). `n = (v & 0x38) >> 3; n++;` computes the count in `$v1`, where one expression uses `$v0` first (`PlayerStats_SetArcadeCourseFlags`).
- **A local of a narrower or wider type.** An `unsigned char` local for a buffer index (`psxViewLoop::Enter`), a `short` for an arrow width (`NumberPicker_Draw`) or a boost rpm (`EngineCurve_SetupTurbo`), `int` copies of values the game compares more than once (`CardMenu`'s slot status, `psxViewLoop::UpdateDisplay`), an `int` for an `lb`'d spacing (`ButtonPrompt_Init`), and an `int` command parameter where callers pass an `unsigned char` (`McCard_StartTransfer`).
- **An assignment after the block it is hoisted into.** `better = 0;` after `RaceRecord_AddLap`'s lap shift gives the game's two `move a1,zero` (one in the branch's delay slot, one after the shift); before the `if`, GCC sets it once. `Timer_StartFrame` returns the time it stores, `CarParams_BuildFromSetup` returns `CarParams_Build`'s result, and `Matrix_FromEuler` and `Matrix_Mul` return their matrix (which gives `Matrix_SetEuler`'s stores through `$v0`).
- **Returning a value keeps `$v0` live.** `Timer_StartFrame` returns the time it stores, `CarParams_BuildFromSetup` returns `CarParams_Build`'s result, and `Matrix_FromEuler` and `Matrix_Mul` return their matrix (which gives `Matrix_SetEuler`'s stores through `$v0`).
- **A pinned register.** `CdAudio_WaitIdle` keeps `&g_CdAudio` in a `register ... asm("a0")` variable.
- **A frame with nothing in it.** `CarModel_InitStub` is empty but has a 16-byte frame: an unused `int[4]` local gives it.

### Loads and stores

- **Chained assignments store the last target first.** `p->x0 = p->x2 = v;` stores `x2`, then `x0`, which is the game's order in the menu quads (`Menu_AddGouraudQuad`, `Menu_DrawColorSwatch`), and it also gives the game's registers for `p->c0 = p->c2 = q->top | 0x3a000000;` where two statements through a local don't.
- **Loads before stores.** The game's C++ was compiled without strict aliasing, so GCC won't move a load above a store through another pointer. Where the game loads first, the source reads into a local before the stores: `psxViewLoop::UpdateDisplay` and `psxViewLoopDoubleBuffer::BeginDraw` read their fields into `int` locals, `CarModel_Draw` reads the instance's fields up front, `McCard_StartTransfer` reads the file size before filling in the state, `McOp_Transfer` reads the buffer, remaining count, index, sector map and offset first, `McOp_Create` reads the index before setting `*buf`, and `KanjiFont_FindGlyph` reads the font's fields before the `wideMode` test.
- **A load hoisted above a branch.** `KanjiFont_RenderGlyph` reads the glyph code (`int code = glyph->code & 0x7f7f`) before testing `rendered`, as the game does.
- **Store order.** GCC keeps the source's store order, so it has to be the game's: `McCard_StartTransfer` needs command, sector map, buffer, offset (found by trying the 24 orders), `NumberPicker_Draw` stores the x fields before the y ones, `KanjiFont_AddGlyphQuad` sets the packet pointer between the CLUT and the texture page.
- **Struct copies.** A camera copied as a struct of 26 `int`s gives word loads and stores; as a `char` array it gives `lwl`/`lwr` (`CarModel_DrawShadow`). Two `signed char` globals copied as one 2-byte struct give the game's two `lb` from one base (`PadButtons_Init`), and four words copied as one `PadState` give four loads, then four stores (`PadButtons_Read`). `RaceRecord_AddLap` moves 9 laps down as one 180-byte struct (`TimeRecords9`), which GCC copies in a loop of 16 bytes, as the game does.
- **A pointer walked as a cursor.** `ReplayData_BuildGhost` writes the lap at `rec += 0x100` and its block at `rec += 0xe0`. With `rec + 0x100` and `rec + 0x1e0`, GCC gives the record and the base each other's registers (found from a permuter output). `GhostEvent_ApplyFile` advances `file += 0x62c` before its struct copy, so the copy loop's end is computed from the advanced pointer, where GCC otherwise folds both offsets into one.
- **A pointer incremented before the store.** `h++; ...; h[-1] = n;` puts the `addiu` ahead of the store, which then uses offset -1 (`PadButtons_Update`). `n++; chain->sectors[n - 1] = i;` does the same for an index (`SectorMap_Alloc`).
- **A stack buffer with room in front.** `SpuFile_Load`'s frame is 16 bytes bigger than its `0x800`-byte sector buffer needs, and the buffer starts at `sp+0x20`: it is `uchar buf[0x810]` used from `buf + 0x10`, where `SpuFile_ProcessSector` copies a sector's last few bytes in front of the next.
- **One load, then the copy.** `SpuFile_ProcessSector` reads `headerLeft` and `spuLeft` once into a local, clamps a copy of it, and stores `rem - n` back; with `l->headerLeft -= n` GCC reloads the field.
- **Offsets computed up front.** `ReplayDir_DrawUsageBar` sets `left = x - 0x80` and `top = y - 4` as its first locals, which puts them in saved registers in the prologue, as the game does. With `x - 0x80` written at each use, GCC computes it later.
- **A global's address through a local.** `GameState *state = &g_GameState;` and then `&state->garages[1]` loads the address and adds the field offset with its own `addiu` (`SaveFile_CopyGarageToPlayer2`); `&g_GameState.garages[1]` folds the offset into the `%hi`/`%lo` pair. In `GameState_WriteSave` the local keeps the address in a saved register, loaded before the first call. `FUN_80068708` (`soundvsync.cpp`) takes `&g_SoundVSync` into a local before passing it with `&g_GfxIrq.vsyncCallbacks`, which loads the second argument's `lui` first.
- **A constant through a local.** `TimeRecord_Init` stores `-1` to the time, then sets `empty = -1` and stores `empty` in the loop: that copies the register before the loop count is loaded, as the game does (found with permuter); with `-1` in the loop, GCC loads the count first. `SectorMap_Init` stores a `short free = 0x3c0` local in its loop, which loads the constant before the loop's other registers. `Pad_UpdateVibration` loads `vibration1` into `port` after its last use (`port = dev->vibration1;`) and computes `b = port >> 4;` later, which gives the game's early `lhu` with the `sll` and `sra` in later delay slots; a new local, or `b` computed at once, loads it late.
- **A dead local reused.** `Pad_UpdateVibration` loads `vibration1` into `port` after its last use (`port = dev->vibration1;`) and computes `b = port >> 4;` later, which gives the game's early `lhu` with the `sll` and `sra` in later delay slots; a new local, or `b` computed at once, loads it late.
- **Signed and unsigned halfwords.** The field types decide `lh` or `lhu`: `KanjiFont_FindGlyph` reads the texture page and CLUT as `short` for the game's `lh`.

### Conditions

- **`xori`.** `x ^ 1` in an `int` local gives the game's `xori` (`Tim_LoadClut`, `CarWork_HasFullSuspension`), and so does an inline function returning `== 1` that is then tested (`ReplayDir_IsOk`); `!x` gives `sltiu`. `PlayerStats_SetArcadeCourseFlags` tests an inline function returning `(v >> 2 & 1) ^ 1`; written in the `if`, or with `!`, the test is folded into the branch.
- **A result computed before the test.** An inline function returning `a && b` (`FUN_80060efc`), or `|` instead of `||` (`Time_FormatDiff`'s `0xffffffff` tests, `Credits_FormatCommas` with an `int` holding `d != 0`), `PlayerStats_SetEventResult`'s `(cur == 0) | (place < cur)`, and `Records_GetSectorTime`'s two -1 tests (`&`, then `|`).
- **A comparison kept as a value.** `state = p < end; state ^= 0x53;` gives the game's `sltu` and `xori` (`McPort_AllocBlocks`); `(p < end) ^ 0x53` as one expression is folded into a branch, as is `p < end ? 0x52 : 0x53`.
- **Checks and-ed into a flag.** `ok &= a == b;` gives the game's `andi ok,ok,1` in the branch's delay slot, then `ok = 0` when the test fails (`ReplayDir_IsValid`).
- **Both tests, then an `and`.** The game evaluates both sides of a label test and `and`s them; `(ly < limit) & (top < ly)` gives that, `&&` gives two branches (`PowerGraphView_DrawAxis`).
- **A -1 test as `nor`.** The game tests a time against -1 with `nor` and a branch on zero, where `x == -1` in an `if` gives `li` and `beq`. An inline function returning `rec->time == -1` gives it (`TimeRecord_IsEmpty`); in an expression evaluated as a value (`Records_GetSectorTime`) GCC uses `nor` and `sltiu` by itself.
- **Nested `if`s against a fold.** `if (f != -1) { if (f >= -1) ... }` keeps the game's `beq` and `slt`; as one condition GCC folds it into `f >= 0` (`PowerGraphView_DrawGrid`). `PlayerStats_SetArcadeCourseFlags` nests `course >= 0` and `course < 32` for the game's `bltz` and `slti`, which `&&` folds into one unsigned test.
- **A subtraction kept for the test.** `v = (v + 0xff) >> 8; v -= 1; if (v == -1)` keeps the game's `addiu -1` and compare with -1; written as one expression, GCC tests the shift against 0 instead (`FUN_800834fc`).
- **Branch sense.** `h = 0x1700; if (!glyph->wide) h = 0xf00;` gives the game's `bnez` with the first value in the delay slot; `h = wide ? 0x1700 : 0xf00` gives `beqz`. `NumberPicker_Update` puts its body inside `if (pad != 0)` so the `pad == 0` test jumps to the final `return`.
- **Two returns of 0.** `PlayerStats_SetEventResult` returns `result` (still 0) for a negative event and a literal 0 when `place` is 0: the first goes through `result`'s register, the second sets `$v0` in the branch's delay slot. With one form for both, GCC merges them.
- **Early returns.** `CarInfoA_IsAvailable` returns from each `case` (the `xori`s are copied into the branches). `KanjiFont_RenderGlyph` wraps its body in `if (!glyph->rendered)` rather than returning early.
- **Nested `if`s with the result set before each test.** `McCard_StartCreate` sets `result` to 5, then 1, 6, 7 and 9 before each nested test (`McCard_StartTransfer` to 5, 1 and 8), which puts each value in the branch's delay slot.

### `switch`

- **Case order follows the game's tests.** A `switch` on an event that the game tests `== 1`, `< 2`, `== 0` has an empty `case 2` (the card menu states). Where the decision tree tests `< n + 1` right after `== n`, the `switch` has an empty case below n (`case 0: break;`). `ButtonPrompt_Init` has a `case 0` beside `default` and its cases in the order 0, 4, 2, 6. The case bodies follow the game's block layout, which also shows which cases fall through or share a tail through a `goto` (`McOp_Transfer`'s remap block, shared by phase 1 and the retry path).
- **Per-case assignments.** `Part_Lookup` sets the field offset in every case rather than once after the `switch`.
- **`switch (st = *status)`** gives the game's copy of the index (`CardState_CheckSlot`).
- **Jump tables** go in the file's own `.rodata`, so a file whose table sits between other files' tables has to be split (`garage2.cpp`).

### `setjmp`, varargs and inline assembly

- **`setjmp`.** `switch (setjmp(&ctx)) { case 0: ...; break; case 1: return 0; } return 1;` gives the game's test (`GzipStream_Continue`).
- **Varargs.** There is no `stdarg.h`; `Overlay_StartAt` reads its arguments from `__builtin_next_arg(entry)`. Indexing the argument area directly keeps a pointer in a register, and taking `&entry` puts `entry` in memory.
- **Unaligned and 24-bit accesses.** GCC emits `lwl` and `lwr` as a pair, `lwl` first, and masks whole words for a 24-bit OT link. Where the game splits the pair, orders it the other way, or copies a link with `lwl`/`swl`, each instruction is its own `asm` statement: `memset`'s lone `swr` and `swl`, `Lz_Decompress`'s loads (`lwr`, then `lwl` only for a copy) and its word copy, and the 24-bit OT links of `KanjiFont_AddGlyphQuad`, `Prim_AddDrawMode` and `FUN_80081cc8` (`lwl` from the entry, `swl` to the packet, then the packet's address shifted left 8 `swl`'d to the entry). `Text_GetAdvance`'s kerning load gets the game's `lwr`-first order the same way. An `asm` output written `=r` instead of `+r` gives the value a short live range, which got `Lz_Decompress` the game's register. Non-`volatile` `asm` can be scheduled away from where it is written; `volatile` keeps the game's order (`KanjiFont_AddGlyphQuad`).
- **A delay slot.** `GzipStream_Begin` puts `move $sp` in the `jal`'s delay slot with a `.set noreorder` `asm` around the call.
- **GTE code** goes through `include/gte.h`'s register moves and commands.

## Not solved yet

- **The address in `$a0` first.** The game loads a global's address into `$a0` (sometimes before the prologue), moves the incoming arguments up to `$a1`-`$a3`, and then copies the address to a saved register, as if setting up a call. GCC loads the saved register directly. Seen in `Overlay_Load`, `CdAudio_Init`, `Music_Stop`, `CdAudio_VSync`, `CdAudio_OnSync`, `CdAudio_OnReady`, `CdAudio_ResetRead`, `CdAudio_ResetStream`, `CdStream_ReleaseSector`, `CdStream_WaitSector`, `CdAudio_OnReadSector`, `RaceFont_OnSector`, `McOp_Create`, `McOp_Transfer` and `McOp_Format`. `McCard_GetResult` is related: it keeps `&g_McOp_Port` in `$a0` and loads through it, where GCC builds the address into each load. Tried without success: inline helpers (with the pointer as their first parameter too), references, `register` variables (also pinned to `$s1`), C++ member functions (inline, called on the global), casts through `void *`, other orders, GCC 2.95 and permuter.
- **Code that falls through into the next function, and tail calls.** GCC 2.8 makes neither. `CdAudio_RunScript` sets up arguments and falls into the next function; `Cd_ReadSync`, `FUN_8007abf8` and `FUN_8007ad1c` shift a sector into a byte offset and fall into the byte-offset function; `FUN_8007da9c` falls into `FUN_8007daac`; `FUN_80081ff8` loads `&g_CdAudio` and falls into `CdStream_GetReadPtr`; `CdGetSector_Thunk` is a lone `j CdGetSector`.
- **Strength reduction the game doesn't do.** GCC gives a loop's fields their own pointer: `MachineTest_InsertRecord` (where the inline helpers of [A record's address added to the index](#addresses-of-globals) didn't help, and permuter only improved it with an `if` whose two arms are the same), `Boot_ShowSplashScreens` (which takes the register the game uses for `D_80033DC0`'s high half; 2.5 hours of permuter didn't remove it), and `CardState_PlayList`, `CardState_GhostList` and `CardState_ReplayEntryList`, where the game hoists the invariants but stores each field of a row through its own copy of the row's address. Tried: `goto` and `while (1)` loops, a row struct, bitfields, references, inline accessors, `-O1`, turning off strength reduction or the CSE passes.
- **A constant left in the loop.** GCC 2.8's loop pass hoists a loop-invariant constant when `threshold * savings * lifetime >= insn_count`. Here `threshold` is 1 + the free registers (doubled when the loop makes no call) and drops by 3 for each insn already moved; `lifetime` is the distance from the constant's set to its use; `insn_count` is the loop's size. `-dL` dumps the decisions. `Replay_Unpack` (65 insns) loads `Replay_GetCarParams`'s `0x14fda` on each pass, while the same accessor in `ReplayData_BuildRace`'s 43-insn loop is hoisted. With an offset local set before the multiply (lifetime 4), or set after it but before the base (lifetime 3), the constant is hoisted in both. As a literal, or set right before its use (lifetime 1), it stays in both. A lifetime of 2 would probably split them, but no natural form gives it.
- **The loop's end address computed in the loop.** `McPort_MapSector`, `McPort_RemapBadSector`, `McDir_FindFile`, `McPort_ResetDir` and the marking loop of `McPort_RebuildBlockUse` compute `port + K` for the exit test on each pass, in a delay slot or before the pointer's increment. A `do`-`while` hoists it; a `goto` loop keeps it in the loop but after the increment (or in the branch's delay slot), and after the loop GCC reuses the pointer where the game computes the address again. `McPort_RemapBadSector` also keeps 0 in a register for a store. Tried: index loops (GCC keeps the index), `for` and `while` loops, `goto` loops with the end in a variable set before the test, `e++` and `++e` in the test, GCC 2.95 and permuter (15 minutes each). The permuter matched `McPort_ResetDir` only with an `if` whose two arms are the same, a block boundary that isn't real code.
- **A record's fields through copies of one address.** `ReplayDir_CheckEntryCrc`, `ReplayFile_StartReadEntry` and `ReplayDir_AddEntry` compute an entry's address once (base after the index) and then copy the register for each field (`move v0,v1`), keeping the full field offsets. Written as `dir->entries[i].x`, GCC adds the base first; through an entry pointer it adds the entries' offset into the pointer; `(dir->entries + i)->x`, references, inline accessors and nested structs don't give the copies either. permuter matched `ReplayDir_CheckEntryCrc` only by reading the size through an `int *` to it. `ReplayDir_DeleteEntry` (2 words) and `ReplayDir_IsValid` (10) have the related loop form: the index times `0x5c` kept, the base added at each access.
- **A load a pass ahead.** `Lod_Select` walks a pointer from `table - 8`, loading the next distance one pass early; no loop form gives it.
- **Division by a constant.** `Cd_LbaToPos` divides with `div`, where GCC multiplies by the reciprocal. Inline functions give `div`, but the registers still differ.
- **Every field before any store.** `Text_DrawGlyph` (with its OT links as `asm` now) computes all of a packet's fields before the first store, and reads the CLUT and texture page as one word, then as two halfwords for the accent. Computing the fields into locals first runs out of temporaries and spills a saved register. `Text_GetAdvance` (its load order solved) adds the rows offset to a separate rows pointer and multiplies with `multu`, where every form tried (unsigned operands, a 64-bit product) gives `mult`.
- **One byte loaded twice.** `McHeader_SetTitle` loads the first title byte with `lb` for the loop test and `lbu` for the code, and the second byte before both; GCC loads it once.
- **Constants in registers before a loop.** `EngineCurve_BoostFactor` matches but for its `switch` case values, which the game loads into registers before the loop.
- **The argument registers.** The twelve rounding multiplies in `enginecurve.cpp` (`Fixed_Mul32`, `Fixed_Mul`, `Fixed_MulShiftTrunc` and variants) don't reuse the argument registers where GCC does.
- **Handwritten code.** Some functions keep values in registers in ways GCC never would, and stay assembly with readable C++ under `NON_MATCHING`: `Inflate_Codes` (keeps its locals in `$t` registers across the callbacks and loads its constants back into `$t8`, `$s3`, `$s2` and `$t9` after each), the GTE functions in `carmodel.cpp`, `gte.cpp` and `cdstream.cpp` (software-pipelined), and `Stack_Check` (copies `$sp` into `$s3`, which C++ gets only through an `asm`, two instructions off).
- **Register allocation only.** The shape matches and only the registers differ, and nothing tried so far (permuter on most) fixed it: `PowerGraphView_DrawAxis`, `PowerGraphView_DrawCurve`, `CarModel_Init`, `CarModel_Draw`, `Tim_LoadToSlot`, `Setting_Interpolate`, `GameData_Relocate`, `GameData_RelocateTable`, `Desc_ScaleFields`, `CarSpec_Resolve`, `CarParams_GetDriveLayout`, `CarParams_Build`, `CarWork_ApplySetting` (the saved registers of `work` and the gear index swapped), `LodTable_SquareDistances` (pointer and end swapped), `Gpu_TransferImage`, `Camera_Update`, `FUN_8007db9c`, `Cd_ReadInflate` (`$t0` and `$t1` swapped), `CardMenu_EntryListCallback`, `FUN_800824ac`, `Matrix_ShiftRot`, `Inflate_Run` and `Inflate_BuildHuft` (which variables get saved registers), and `KanjiFont_RenderGlyph` (`font` and `glyph` swap saved registers, and the row bits and the first sum swap `$a1` and `$a2`).
- **Scheduling only.** `CarInfoA_GetData` (the data offset's `and` before the colour count's `andi`), `GzipStream_Begin` (one copy of `stream` three instructions early), `WheelMesh_Scale` and `CarModel_BuildWheels` (loads and multiplies), `CdAudio_ApplyVolume` (products and clamps). `PowerGraphView_DrawRpmAxis` divides before its text flags are set, where the game divides after.
- **Further off.** `CarWork_GetSettingRange` (one more saved register, more shared case tails), `EngineCurve_Resample`, `Gearbox_ComputeRatios`, `EngineCurve_Build`, `EngineCurve_GetPerf` and `EngineCurve_TorqueAt` (frame layout, statement order, registers).

## Working notes

- **Permuter results need checking.** Its best candidates often change what the code does: an `if` around a call that must always run (`Inflate_Run`), a call doubled into both branches (`GzipStream_Begin`), a `do { } while (0)` around a few statements, or a temporary reused across unrelated values. Some gains are real but come from an odd form that points at the real one: reusing `phase` for `code & 0x7f7f` led to the `code` local in `KanjiFont_RenderGlyph`, and a split `stride` assignment was kept as it is.
- **Trying every order.** For a few statements whose order matters, compiling every permutation is quicker than the permuter (`McCard_StartTransfer`'s four stores).
- **Declaration order** of locals made no difference in the cases tried (`McCard_StartTransfer`, `KanjiFont_RenderGlyph`).
